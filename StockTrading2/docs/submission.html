1. 프로젝트 개요

기존에 제공된 실습용 스캐폴드(사용자/주식/거래/포트폴리오 CRUD 일부 및 매매·분석 로직이 비어있는 상태)를 기반으로, 과제 요구사항에 명시된 CRUD 공백을 채우고 매매 실행 로직·분석 기능 8종을 구현했다. 데이터 접근은 JPA와 MyBatis를 병행 적용했으며, 거래 처리 과정에는 AOP를 적용해 감사 로그(Trade Audit Log)를 남기고, Spring Boot Actuator로 헬스체크/애플리케이션 정보를 노출했다.

4. ERD / 엔티티 구조

User (1) ──────< Portfolio >────── (1) Stock │ id, username, password, │ id, code, name, │ email, balance │ currentPrice, previousPrice │ │ └──────< Transaction >──────────────┘ id, type(BUY/SELL), quantity, price, totalAmount, transactionDate TradeAuditLog (독립 테이블 - AOP 감사 로그 전용) id, userId, stockId, type, message, totalAssets, totalReturnRate, createdAt
  • User – Portfolio: 1:N (한 사용자가 여러 종목 보유)
  • Stock – Portfolio: 1:N (한 종목을 여러 사용자가 보유)
  • User – Transaction: 1:N, Stock – Transaction: 1:N
  • TradeAuditLog: 다른 엔티티와 FK 연관관계를 맺지 않고 userId/stockId를 단순 컬럼으로 보관 (감사 로그는 트랜잭션 롤백과 무관하게 독립적으로 남아야 하므로 연관관계 대신 값으로만 참조)

6. JPA / MyBatis 병행 적용 기준

단건 조회·CRUD·트랜잭션성 로직은 JPA(영속성 컨텍스트, 더티체킹)로 처리하고, 여러 테이블을 조인·집계해야 하는 통계성 조회는 SQL을 직접 다루기 쉬운 MyBatis로 분리했다.

영역기술이유
User/Stock/Portfolio/Transaction CRUDJPA단건 엔티티 중심 조작, 변경 감지를 통한 자동 반영
매매 실행 (executeTrade)JPAUser/Stock/Portfolio 상태를 하나의 트랜잭션에서 함께 변경해야 하므로 영속성 컨텍스트 활용이 유리
포트폴리오 평가손익 / 종목별 거래내역(전체)JPA기존 연관관계(Portfolio↔Stock, Transaction↔User/Stock)를 그대로 조회·매핑
총자산 · 총수익률 · 거래통계 · 일별거래내역MyBatisSUM/CASE/GROUP BY 등 복잡한 집계 SQL을 직접 작성하는 것이 JPQL보다 명확하고 성능상 유리

MyBatis 매퍼는 StockMapper 인터페이스 + StockMapper.xml로 구성했으며, mybatis.configuration.map-underscore-to-camel-case: true 설정으로 스네이크케이스 컬럼을 DTO 필드에 자동 매핑했다.

7. AOP 적용 내용

매매 처리(TransactionService.executeTrade)를 TradeAuditAspect의 @Around 어드바이스로 감싸 실행 시간을 측정하고 성공/실패 여부를 로깅한 뒤, 결과와 무관하게 TradeAuditLog 테이블에 감사 기록을 남기도록 구현했다. 실제 저장은 TradeAuditLogService에서 @Transactional(propagation = Propagation.REQUIRES_NEW)로 처리하여, 매매 트랜잭션이 롤백되더라도(예: 잔고 부족) 감사 로그는 별도 트랜잭션으로 독립적으로 커밋되도록 했다.

구성 요소내용
Pointcutexecution(* com.skala.stock.service.TransactionService.executeTrade(..))
Advice@Around - 실행시간 측정 + 성공/실패 로깅 + 감사로그 위임
감사로그 저장TradeAuditLogService.recordSuccess/recordFailure (REQUIRES_NEW)
성공 시 기록메시지 + MyBatis로 재계산한 총자산/총수익률 스냅샷 저장
실패 시 기록실패 사유 메시지 저장 (자산 정보는 변동 없으므로 생략)

실제 실행 테스트 시 남은 로그:

[거래 성공] userId=3, stockId=4, type=BUY, quantity=2, 15ms
[거래 성공] userId=3, stockId=4, type=SELL, quantity=1, 2ms
[거래 실패] userId=3, stockId=7, type=BUY, quantity=1000, 0ms,
           reason=잔고가 부족합니다. 필요 금액: 800000000, 보유 잔고: 2950000

11. 특이사항

기존 스캐폴드는 교육생 실습을 위해 매매 실행, 포트폴리오 갱신, 분석 컨트롤러/서비스/매퍼가 의도적으로 비어 있는 상태였다. 특히 TradeAuditLog 엔티티는 사용되지 않은 채 "REQUIRES_NEW 트랜잭션 예제"라는 주석과 함께 미리 준비되어 있었는데, 이는 AOP + 트랜잭션 전파 실습을 염두에 둔 설계로 판단하여 AOP 적용 대상으로 그대로 활용했다.
